# Mini Workspace Explorer

A lightweight, in-browser file explorer and text editor built with Next.js (App Router), TypeScript, and Tailwind CSS.

---

## Getting Started

### Prerequisites
- Node.js 18.17+ or newer
- npm / pnpm / yarn

### Installation & Run

1. Clone or download the repository.
2. Install dependencies:
   ```bash
   npm install
   ```
3. Start the development server:
   ```bash
   npm run dev
   ```
4. Open [http://localhost:3000](http://localhost:3000) in your browser.

### Available Scripts
- `npm run dev` – Starts the Next.js dev server.
- `npm run build` – Builds the application for production.
- `npm run start` – Runs the built production server.
- `npm run lint` – Runs ESLint checks.

## File-System Data Structure

Rather than storing files in a deeply nested recursive object, the workspace uses a **flat normalized dictionary/hash-map** (`Record<string, WorkspaceItem>`):

```ts
export type ItemType = "folder" | "file";

export type WorkspaceItem = {
  id: string;
  name: string;
  type: ItemType;
  parentId: string | null; // null for the root folder
  content: string;         // text content for files
  createdAt: number;       // timestamp
  updatedAt: number;       // timestamp
};
```

### Why a Normalized Map?
- **O(1) lookups & updates:** Accessing, renaming, or updating file content does not require traversing or rebuilding deep nested object trees.
- **Fast parent/child queries:** Children are computed on demand by filtering on `parentId`.
- **Easy serialization:** Directly serializable to and from JSON for `localStorage`.
- **Simpler path resolution:** Breadcrumb paths and ancestor chains are generated by walking up `parentId` pointers to the root.

## State Management Approach

All state is centralized in a custom React hook: [`useWorkspace`](src/hooks/useWorkspace.ts).

- **Local React State:**
  - `items`: The normalized dictionary holding all folders and files.
  - `selectedFolderId`: The ID of the currently active folder.
  - `expandedIds`: A `Set<string>` containing folder IDs that are open in the sidebar tree.
  - `openFileId`: The ID of the file currently being edited (or `null` when in folder view).
  - `searchQuery`: Active search keyword.

- **Persistence Layer (`localStorage`):**
  - On mount, state loads from `localStorage` (`workspace_v1`). If no previous state exists, it initializes with starter dummy files from `seed.ts`.
  - Every state mutation triggers a background sync to `localStorage`.
  - Storage errors (e.g. quota limits or private browsing restrictions) fail gracefully without breaking UI execution.

## Important Implementation Decisions

1. **Client-Side Hydration Guard (`next/dynamic` with `ssr: false`)**
   - Since initial state is read from browser `localStorage`, server-side rendering can cause hydration mismatches. The `Explorer` component is loaded dynamically on the client side with a lightweight fallback loader.

2. **Recursive Cascade Deletions**
   - When a folder is deleted, an iterative stack traversal (`collectDescendantIds`) collects all nested subfolders and files to ensure no orphaned items remain in storage.

3. **Name Validation & Collision Handling**
   - File/folder names are validated before creation or renaming. It blocks empty strings, forward/backward slashes (`/`, `\`), names over 64 characters, and duplicate names within the same parent folder (case-insensitive).

4. **Keyboard-Friendly Editor**
   - The file editor supports `Ctrl + S` / `Cmd + S` for quick saving, dirty state indicators (unsaved badge), and live statistics (line count, word count, character count).

5. **Non-destructive Navigation**
   - Selecting a search result automatically reveals and expands the necessary folder path in the sidebar tree and navigates directly to the target item.
